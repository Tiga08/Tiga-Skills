# 翻译约定

主会话和每个子 agent 都按这份约定校对和翻译。`check.py` 会按「结构一一对应」逐块比对，违反时报错。

## 校对原文块

翻译之前，先对照原版修正 `chunks/NNN.src.md` 里的提取错误，直接在原文块上改。只修提取错误，不删内容。

- **看原页**：PDF 用 `python3 <脚本目录>/render.py <原版> <工作区> <页码范围>` 把原页渲染到 `<工作区>/pages/`，再用 Read 看。页码来自块里的 `<!-- page N -->` 标记。公式密的页加 `--scale 3 --split 3`，把每页放大并横切成三条；同目录的 `p-NNNN.txt` 是该页的文字层，可以用来核对公式符号和拼写。EPUB 一般不需要看原页。
- **阅读顺序**：双栏排版的段落顺序乱了，或者图注插在了段落中间。
- **被分页切断的段落**：合并成一段。页码标记落在段落或列表中间时，挪到段落或列表之后；否则拼接时去掉标记，列表会被拆开。
- **非正文内容**：混进正文的页眉、页脚、页码、图表里的文字（坐标轴刻度等）删掉。标题作者块是 skip 的，块里的作者脚注（如「两人贡献相同」）写进题头。
- **标题**：被误认成标题的行改回正文。标题层级要调整：H1 只留给题头里的书名或论文标题，正文最高一级用 `##`，往下依次递减；EPUB 的书也要调。提取时丢掉的章号、部分号，按原页补回标题里（如 `### CH 1 A Design Process…`），全书各章写法一致。
- **公式**：给对齐公式补上 `\begin{aligned}`；占位符 `<!-- formula-not-decoded -->` 补成 LaTeX；丢了上下标的行内符号写成 `$…$`。
- **表格**：结构错了要改正；有合并单元格的写成 HTML 表格；补回原有的加粗。
- **脚注和尾注**：印在本页底部的脚注，混进正文时改成 `[^n]`。书的章末尾注（各章末尾的 Notes 列表，编号每章重新开始）保持原样：正文里的标记写成 `<sup>n</sup>`，尾注列表留在章末。因为引用和定义常常不在同一块里，而且各章编号会重复，所以不要改成 `[^n]`。
- **被识别成图片的文字框**：提示框、原则框、引文框里的文字是正文内容。在原文块里把这类图片行换成框里的文字，用引用块写，不保留图片。
- **图注和格式**：图注和图表的先后顺序与原页一致；补回原页的粗体和斜体。

## 总则

- 全文照译：不摘要、不删减、不加译者评论，保留原文的语气（口语、幽默、自嘲）。
- 只出中文，不做双语对照。
- **结构一一对应**：译文块和原文块的标题、段落、图片、表格、独立公式、代码块、脚注一样多，顺序不变。一个原文段落译成一个段落，不拆也不并；被页面切断的段落应在校对原文块时就合并好。
- `<!-- page N -->` 页码标记留着删掉都行，拼接时会自动去掉。

## 用词

- `terms.md` 里的术语，以及人名、机构名、作品名，第一次出现时写成「中文（原文）」，之后只写中文；原文本身已带括号说明的，不再加。书按章计算「第一次」：各块是并行翻译的，看不到前面的章，读者也常常从中间某章读起。
- 人名用通行译名；查不到通行中文名的（包括华裔和日韩作者），保留原文，不硬造汉字。书名、论文名、文章名用《》。
- 技术术语用该领域中文社区的通行译法；业内普遍直接用英文的词保留英文（如 token）。
- 模型、数据集、软件库、指标的名称保留原文，如 YOLOv3、COCO、PyTorch、mAP。
- 同一个术语全文只用一个译法，以 `terms.md` 为准。确实需要按语境换译法时，在翻译术语表的「说明」列写明。

## 结构元素

- **标题**：保留层级和编号。Chapter 3 或 CH 3 译为「第 3 章」，Part I 译为「第一部分」，Appendix A 译为「附录 A」，如「### 第 1 章 数字产品的设计流程」。
- **图片**：`![…](images/fig-NNN.ext)` 整行照抄，图内文字不改。图注要翻译：Figure 3. 译为「图 3：」，Table 1. 译为「表 1：」。
- **表格**：翻译单元格文字，数字、单位和名称不动。原表有合并单元格时，写成 HTML `<table>`，用 `rowspan`/`colspan`，中间不留空行；其余情况用 Markdown 管道表格。
- **公式**：独立公式 `$$…$$` 的内容与原文块逐字一致，公式里的 `\text{}` 也不译。行内的数学符号写成 `$…$`。带编号的多行公式写成一个 `aligned` 块，编号放在每行末尾的 `&& (n)` 列；单行公式用 `\tag{n}`。范数和花括号写成 `\lVert…\rVert`、`\lbrace…\rbrace`，不要写 `\|`、`\{`，Markdown 会把它们当成转义吃掉。
- **代码**：代码块和伪代码整块照抄，注释也不译；行内代码照抄。伪代码里的数学符号用 Unicode 写，如 θ、β₁、←。
- **算法和定理类标签**：Algorithm 1 译为「算法 1」；Theorem、Lemma、Corollary、Definition、Proof 分别译为「定理」「引理」「推论」「定义」「证明」；证毕符号 □ 照抄。
- **脚注和尾注**：`[^n]` 的引用和定义、`<sup>n</sup>` 尾注标记都照抄，只翻译脚注和尾注的文字。
- **引用**：文献引用标记 `[12]`、`(Smith, 2010)` 照抄。正文里的交叉引用译为「图 3」「表 1」「第 2.1 节」「式 (4)」。
- **参考文献、书目**：放在 keep 块里，只把标题译成「参考文献」，条目逐行照抄。
- **链接**：链接文字翻译，地址不动。
- **引文、诗句**：照译，原文用引用块的继续用引用块。

## 题头（header.md）

第一行 H1 是中文书名或论文标题，下一段写原名、作者和出处：

```markdown
# 创造行为

The Creative Act: A Way of Being｜里克·鲁宾（Rick Rubin）著，尼尔·施特劳斯（Neil Strauss）协作
```

```markdown
# YOLOv3：渐进式改进

YOLOv3: An Incremental Improvement｜约瑟夫·雷德蒙（Joseph Redmon）、阿里·法哈迪（Ali Farhadi），arXiv，2018
```

## 翻译术语表（terms.md）

只收核心概念和容易译得不一致的词，不收常用词。术语多时按主题分 `###` 小节。

```markdown
## 翻译术语表

以下为本译文的统一译法。

| 原文 | 译法 | 说明 |
|---|---|---|
| bounding box prior | 先验框 | |
| objectness score | 目标置信度 | |
```

子 agent 的新术语写进 `chunks/NNN.terms.md`，用同样的表格列，不加标题。
